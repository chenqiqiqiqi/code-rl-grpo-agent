# 代码大模型 RL 后训练：奖励设计对比与单轮 GRPO vs 多轮 Agent RL

以 Qwen2.5-Coder-7B-Instruct（M0）为基座，在单卡 RTX 4090D 48GB 上基于 verl + vLLM 搭建 LoRA GRPO 训练与隔离沙箱评测流程，回答两个问题：

1. 奖励函数：二值奖励（全部测试通过）与混合奖励（0.5 × 测试通过比例 + 0.5 × 是否全部通过）有何差别？
2. 在相同新增生成 token 预算下，继续单轮 GRPO 与多轮工具调用 Agent RL，哪种更能提升代码能力？允许调用工具能否带来增益？

## 主要结果

统计方法：每题采样 k=8（关键比较 k=16），报告期望通过题数；逐题配对 bootstrap 95% CI + 符号检验。单种子（seed 42）。

### 第一阶段：奖励函数（从 M0 出发，各 124 步）

| | 开发集 350 题（严格判分） | vs M0 |
|---|---|---|
| M0 | 242.25（69.2%） | — |
| 二值奖励 @124 | 268.38（76.7%） | +26.12 [15.25, 37.12] |
| 混合奖励 @124 = **W** | 276.50（**79.0%**） | +34.25 [22.88, 45.88] |

- 混合 − 二值 = +8.12 [−2.75, 19.00]，**差异不显著**。
- 封存测试集（295 题，同分布，只评一次，宽松判分）：M0 68.6% → W **78.3%**，+28.62 [18.75, 38.75]。
- 收益主要体现为单次采样成功率提升（"磨尖"）。M0 → W（开发集，每题 8 次）：
  - pass@8 解题数 294 → 300：新增 18 题、丢失 12 题（精确 McNemar p ≈ 0.36），覆盖率未见显著变化；
  - 每题 8 次的分布：全对 178 → 251，有对有错 116 → 49，全错 56 → 50；
  - 每题不同解法占比 66% → 24%；训练过程中策略熵 0.15 → 0.03。
- 两分支各再训 60 步均无进一步提升（见 [reports/mixed-extension-analysis.md](reports/mixed-extension-analysis.md)）。

### 第二阶段：等 100 万新增生成 token，从 W 继续训练

C = 单轮 GRPO（160 步，1,000,227 token）；A = Agent RL（`run_python` 工具 ≤ 3 次 + `submit`，34 步，1,014,968 token）。只计模型生成的 token，断点恢复后重跑部分只计一次。

| 单轮 pass@1（宽松判分） | 开发集（k=16） | 测试集（k=8） |
|---|---|---|
| W | 79.2% | 78.3% |
| C | 79.1% | 79.2% |
| A | 78.3% | 78.5% |

C − W、A − W、A − C 均不显著：两种续训方式都**未在 W 基础上进一步提升单轮代码能力**。

Agent 模式下的行为：

- W 在 Agent 协议下有 **26.8%** 的轨迹因编造动作名而无效；A 降至 **1.5%**（测试集 1.4%）；首轮先调用工具测试的比例 66.6% → 99.7%。
- "用工具 − 不用工具"（开发集期望通过题数）：W 为 −9.25 [−17.38, −1.25]（显著变差），A 为 +4.62 [−3.62, 12.75]（不显著）；测试集 A 为 −0.88。
- 结论：在该模型上，Agent RL 的主要作用是恢复对工具协议的遵守，而非提升单次通过率。

完整数字见 [reports/FINAL_SUMMARY_20261002.md](reports/FINAL_SUMMARY_20261002.md)。

## 实验设置

| 项目 | 设置 |
|---|---|
| 训练 | verl GRPO，LoRA r=32 / α=64；每步 4 题 × 8 个回答；学习率 5e-5；low_var_kl 系数 0.001，参照模型 = M0（关闭 LoRA）；token-mean loss，每步一次更新 |
| 采样 | 训练 T=1.0、不截断；评测 T=0.7、top_p=0.8、top_k=20 |
| 数据 | KodCode-V1-SFT-4o（Algorithm/Evol、中/难、纯 assert、仅标准库）；训练题经 M0 k=4 筛选只保留 0<p<1 的题 |
| 划分 | 按 seed_ids 去同源，开发集 350 题、封存测试集 295 题；训练题对 HumanEval+/MBPP+ 做 10-gram + TF-IDF/函数名两轮去污染，剔除 98 道相似题 |
| 判分 | Docker 隔离沙箱（断网、1 核、256MB、4 秒），隐藏测试；主口径为"不计格式"的宽松判分，严格判分作诊断 |

## 工程记录

- **显存**：从 LoRA adapter 继续训练时多占约 4GB，峰值 48.5GB。将 vLLM 显存占比从 0.4 调到 0.35、动态批 token 上限从 7168 调到 4096 后，常规 OOM 消除；权重同步阶段（约 2GB 缓冲）仍有偶发 OOM，用每 10 步检查点自动恢复兜底。
- **等 token 预算**：按实际生成 token 计数截停（预算 100 万），台账在断点恢复时去重。
- **评测**：生成与判分分离；判分服务运行在独立 CPU 虚拟机的 Docker 沙箱中，通过 SSH 隧道与 GPU 服务器连接。

## 局限

- 单种子；检查点之间约有 ±5–10 题的波动。
- 训练题按二值通过率筛选，对混合奖励不完全公平；第二阶段题池取单轮/Agent 有信号题的并集，对 A 稍有利。
- 提升是在同分布（KodCode）测试集上测得；HumanEval+/MBPP+ 未评测，跨分布泛化未验证。
- W 的选择在两分支延长结果已知后作出（协议 v4 补充 7），但封存测试集只在 W/C/A 全部冻结后使用一次。
