## Agent 协议

动作仅 run_python(code, stdin) / submit(code)：`run_python` 必须是严格 JSON；`submit` 可为严格 JSON，或唯一且可解析的 Python 代码围栏兼容提交，后者在审计中标明 `python_fence_fallback`。多围栏、坏 JSON、未围栏代码及语法错误代码不作为兼容提交。最多 3 次工具执行与第 4 轮提交；生成每轮上限 1024，整条上限 4096；初始提示上限 3072，响应缓冲含工具内容 5120，总上下文至多 8192。初始提示超长拒绝，不静默截断。提交后终止；无有效动作、未提交、超过轮数归为策略失败，终局奖励为 0。工具调用本身无奖励，无按报错数量奖励。该兼容协议已做本地回归，仍须 GPU 复测后重新冻结；W/C/A 必须使用同一版本。

工具仅执行公开/自建 stdin，无隐藏 oracle。工具输出按 4096 字符截取，明确截取标记；终局评分不回传模型。工具基础设施失败、未知执行或身份变化导致整批中止，不转零奖励，不继续更新；重新启动须对账，未知 token 保留最坏预留费用。

策略 loss 只覆盖所有 assistant 生成 token。工具消息、环境提示、padding 不计 loss，终局 reward 对该轨迹生成 token 的 GRPO advantage 生效。每题 G=4 完整轨迹，零方差组不人为补信号。保持 actor 重算 old log-prob，rollout log-prob 独立留档；reference 为共同起点，不能误退回 M0。

## 公平评测

W/C/A 都用同一 Agent 协议、相同工具权限、最大轮数、上下文、生成预算、解码设置，报告每题最终提交的隐藏测试通过情况。W 也允许调用工具；不能用单轮 W 对多轮 A 宣称训练收益。另保留各模型单轮评测，观察回归。

保留派生 LCB 199 主评测和 HumanEval+162 / MBPP+373 跨接口评测，三项分开报告。多轮 v1 主结果先限定 stdio LCB；函数题在函数工具适配完成且冻结前仅做单轮迁移，不将 stdio 工具直接套用函数接口。评测执行器 readiness 通过才实际评分，不冒充完整官方成绩。

主指标为整题成功率；同时报告首次/最终提交、失败后修复、工具调用数、无效动作率、生成 token、完整上下文 token、CPU执行量、墙钟时间与费用。按题配对分析，单 seed 不作跨 seed 稳定性结论。

## 预算、恢复和启动门槛

总额 2000 元包含既有 Stage 1 支出；正常预测不超过 1600，余 400 应急。GPU 等待 CPU 的时间仍算 GPU 账单。四条正式 RL（二值、混合、C、A）顺序运行，阶段间停 GPU，模型下载/环境安装也计费。

每批生成前预留完整组最坏 token；生成成功后按实际 assistant token 结算，工具上下文另记成本。预算不足下一完整批时正常结束，保存上一完整更新；剩余 token 报告，不制造虚假满额。触及 max_steps 或异常退出不算正常预算终点。

CPU 源、模型、配置、依赖、工具协议、数据和实际执行身份均需绑定。SFT 可恢复参数/优化器/调度器/RNG/数据进度；RL 账本在 checkpoint 外保存，恢复不得回滚已花 token。正式 freeze 必须包含真实 7B pilot 和同步、恢复、概率路径证据。candidate 配置只是建议，不能替代 freeze。
