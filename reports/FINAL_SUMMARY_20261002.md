# Stage 4 结果汇总（2026-10-02）

基座：Qwen2.5-Coder-7B-Instruct（M0）。LoRA r32，GRPO（每步 4 题 × 8 样本），学习率 5e-5，参照 M0。

- 判分：主口径为"不计格式"的宽松判分（协议 v4 补充 9）；严格口径作诊断。
- 统计：期望通过题数，逐题配对 bootstrap 95% CI + 符号检验。
- 数据：开发集 KodCode 350 题；测试集 KodCode 295 题（封存，只用一次）。HumanEval+/MBPP+ 最终评测暂缓（判分器未就绪，用户决定）。

## 第一阶段：奖励函数（开发集，单轮，k=8 s42，严格口径）

| | 期望通过 | 通过率 | vs M0 |
|---|---|---|---|
| M0 | 242.25 | 69.2% | — |
| 二值 @124 | 268.38 | 76.7% | +26.12 [15.25, 37.12] |
| **混合 @124 = W** | **276.50** | **79.0%** | **+34.25 [22.88, 45.88]** |

- 混合 − 二值：+8.12 [−2.75, 19.00]（k=8）；k=16 时 +7.94 [−2.88, 18.88]。不显著。
- 两分支再训 60 步后无进一步提升（k=16：二值 274.31、混合 271.00），见 `mixed-extension-analysis.md`。
- W 按用户决定取混合 @124（协议补充 7，在延长结果已知后作出）。

## 第二阶段：等 100 万新增生成 token 的单轮 GRPO（C）vs Agent RL（A）

C：单轮 GRPO，160 步，1,000,227 token。A：Agent RL（run_python ≤3 次 + submit），34 步，1,014,968 token。

### 问题 1：训练方式 → 代码能力（单轮，宽松）

| | 开发集（k=16） | 测试集（k=8） |
|---|---|---|
| M0 | 242.25（69.2%，k=8） | 202.38（68.6%） |
| W | 277.25（79.2%） | 231.00（78.3%） |
| C | 277.00（79.1%） | 233.62（79.2%） |
| A | 273.94（78.3%） | 231.62（78.5%） |
| W − M0 | +35.00 [23.50, 46.56] | **+28.62 [18.75, 38.75]** |
| C − W | −0.25 [−10.69, 10.44] | +2.62 [−7.12, 12.25] |
| A − W | −3.31 [−9.12, 2.50] | +0.62 [−6.38, 7.50] |
| A − C | −3.06 [−13.31, 6.94] | −2.00 [−12.75, 8.75] |

**结论**：第一阶段的提升（约 +10pp）在封存测试集上复现。第二阶段的单轮续训与 Agent RL 都未在 W 基础上进一步提升单轮代码能力，二者之间也没有可测差异。

### 问题 2：允许多轮 + 调用工具 vs 直接单轮（宽松）

| | 开发集 单轮 | 开发集 Agent | Agent − 单轮 | 测试集 单轮 | 测试集 Agent | Agent − 单轮 |
|---|---|---|---|---|---|---|
| M0 | 242.25 | 245.25 | +3.00（不显著） | — | — | — |
| W | 277.00 | 267.75 | **−9.25 [−17.38, −1.25]** | — | — | — |
| A | 273.00 | 277.62 | +4.62 [−3.62, 12.75] | 231.62 | 230.75 | −0.88 [−7.12, 5.50] |

- 开发集差中差：A vs W 为 **+13.88 [5.50, 22.50]**（显著），说明 Agent RL 修复了单轮 RL 造成的工具使用退化；A vs M0 为 +1.62 [−8.50, 11.62]（不显著）。
- pass@8：A 用工具时更高（开发集 315 vs 304；测试集 266 vs 253），能解出的题更多，但单次通过率没有提升。
- 行为：W 在 Agent 协议下有 26.8% 轨迹因自造动作名而无效；A 降到 1.5%（测试集 1.4%）。A 首轮调用工具的比例为 99.7%，大多数轨迹测 1 次即提交。每条平均生成 612 / 566 token（开发集 / 测试集），单轮约 150。
- **结论**：在这个模型上，允许多轮调用工具没有带来显著的通过率提升。Agent RL 的主要效果是让模型恢复守协议、会用工具，而不是提高单次正确率。

## 解读与局限

- 基座已经过大量后训练，RL 收益集中在前约 120 步，表现为"磨尖"：pass@1 上升，pass@8 基本不变。这与公开文献在同一模型上的结果一致：AceCoder HE+ −1.2 / MBPP+ +0.3；KodCode 的 GRPO HE+ ±0 / MBPP+ +2.4。
- 局限：
  - 每种方法只跑了 1 个 seed，检查点之间有约 ±5–10 题的波动。
  - 第二阶段题池按"单轮或 Agent 有信号"取并集，对 A 稍有利。
  - HumanEval+/MBPP+ 未评。
- 建议：换用提升空间更大的基座（如 Qwen2.5-7B-Instruct 或 Qwen2.5-Coder-1.5B-Instruct）并增加 seed 数。
